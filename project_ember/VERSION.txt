Project Ember v0.9.4 — Mobile UX Foundation (UI-1)
- Adds UiMetrics dp conversion using screen DPI, viewport/window stretch ratio and UI scale; supports dp scale 0.8–1.6 and refreshes after resize/settings changes.
- Adds a SafeAreaContainer that recalculates display safe insets when the window/viewport changes.
- Adds TouchGestureRouter signals for tap, double-tap, long-press, drag, pinch and two-finger pan, with UI hit-testing and emulated-mouse duplicate suppression.
- Adds Haptics, ToastManager/Toast, ConfirmDialog, BottomSheet and IconButton foundations plus initial SVG menu/settings/confirm/cancel icons.
- Adds Android Back handling, background strategic autosave / battle autopause, Sensor Landscape orientation and confirmed one-second New Campaign reset.
- Campaign writes now use a validated .tmp file and .bak rotation/recovery. Existing campaign JSON version and key schema are unchanged; saving during unfinished combat remains blocked.
- Converts shared UI theme, SettingsPanel, existing strategy/battle HUD offsets/button targets and FPS overlay to dp calculations.
- UI-1 does not yet replace the legacy battle/map layouts or route world commands through the new gesture signals. Those are UI-2/UI-3 work.
- Godot 4.3 GL Compatibility remains the target. Safe-area insets, actual dp sizing, haptics and app lifecycle require physical Android validation.

Project Ember v0.9.3 — Combat Effects & Sound
- Connects pooled hit, charge, rally, death, muzzle and projectile trail effects to tactical combat events.
- Adds original procedural combat sounds for melee, spear, cavalry, bow, arrow impact, death and commander rally.
- Scales fixed visual/audio pools by quality: Low 8/4, Medium 14/6, High 18/8.
- Caches the glowing bolt mesh and material; no per-hit effect nodes are allocated.
- Reuses the existing SFX volume setting and preserves damage formulas, saves, movement, unit roles, formation slots, collision and touch controls.
- Godot 4.3 GL Compatibility remains the target. Physical Android sound balance and performance checks are still required.

Project Ember v0.9.2 — Battlefield Biomes & Terrain
- Adds grassland, woodland, highlands and marsh battlefield profiles selected from neighboring strategic hex terrain.
- Biome-specific ground textures/palettes, vegetation density and low-poly props create repeatable battlefield variation.
- Adds fallen logs, rock shelves, shallow marsh pools and reeds with quality-aware decoration counts.
- Tactical HUD displays the terrain name.
- The flat ground collision body and bounds are unchanged; biome decorations add no blocking colliders.
- Campaign save schema, unit roles, combat formulas, formation slots and tactical input mapping remain compatible.
- Godot 4.3 GL Compatibility remains the target; physical Android FPS/readability checks are still required.

- Each unit now uses two merged vertex-coloured ArrayMesh batches: static body silhouette and an animated action part.
- Ten cached team/role mesh combinations share a single vertex-colour material.
- Distinct silhouettes and role details are retained for swordsmen, archers, spearmen, cavalry and commanders.
- Added idle/movement animation, melee swings, spear thrusts, bow draw/release, cavalry charge motion and commander banner motion.
- Added shared-material hit flash, falling death animation and quality-capped 8–10 second corpses.
- Selection/target feedback uses one cached ring; health bars appear only when selected, targeted or wounded.
- Core BattleUnit node count is capped at eight including collision, ring and health elements; CI tests 50 unit instances.
- Campaign saves, unit role IDs, damage formulas, speeds, formation slots, collision and input mapping remain unchanged.
- Godot 4.3 GL Compatibility is retained; real Android performance, touch rendering and combat readability still require device testing.
