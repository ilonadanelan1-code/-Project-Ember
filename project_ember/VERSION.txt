Project Ember v0.10.4 — Illustrated Strategic Terrain
- Replaces the repeated flat hex fill with a compact five-column atlas: grassland, forest, highlands, water and continent-scale topographic surfaces.
- Terrain atlas variation is encoded in the MultiMesh instance color alpha band; each cell gets a stable two-way motif orientation derived from axial coordinates, avoiding unsupported CanvasItem custom-instance shader data in Godot 4.3 GL Compatibility.
- At zoom <= 0.22, six-hex LOD chunks use a restrained topographic motif instead of oversized individual terrain symbols.
- The map retains one MultiMesh terrain batch; no per-hex nodes or additional terrain draw calls are introduced.
- Fog-of-war tinting and ownership overlays continue to modulate each instance colour.
- Adds renderer smoke tests for atlas selection, per-instance data, LOD motif selection and single-batch rendering.
- Visual pass follows the Art Bible's warm, matte, stylized tabletop miniature direction and avoids heavy post-processing.

Project Ember v0.10.2 — Fog of War & Chunked Map Streaming
- Field army vision radius: 9 hexes; city vision radius: 4; settler vision radius: 3.
- Newly discovered cells are saved. Previously explored terrain stays visible in a dimmed remembered state; unknown cells remain hidden by fog.
- Enemy armies render only inside current vision; enemy cities remain remembered after discovery.
- Existing campaign JSON version and fields are preserved. Older saves discover the area around current player sources automatically.
- Strategic viewport streaming iterates only explored cell IDs, not all 24,031 world hexes.
- At zoom <= 0.22, discovered terrain aggregates into 6×6 axial LOD chunks and remains one MultiMesh draw batch.
- FPS overlay reports explored count, viewport-known cells, batch instances and LOD scale.
- Includes fog/save/load regression checks and a renderer test confirming 1,024 cells collapse to at most 36 instances in LOD mode.

Project Ember v0.10.1 — Render Batch Performance Hotfix
- Strategic terrain draws through a single viewport-scoped MultiMeshInstance2D batch instead of thousands of per-hex CanvasItem draw commands.
- The hex texture is generated once in memory; per-instance colors preserve terrain and territory tinting.
- City ownership tinting uses a compact claim lookup rather than repeatedly scanning every kingdom for every visible hex.
- Performance overlay now reports CPU process ms, visible map hexes and terrain batch count.
- Includes a renderer smoke test verifying 1,024 tile instances are submitted in one batch.
- The 24,031-hex world, nine AI kingdoms, map navigation, save compatibility and existing tactical gameplay are retained.

Project Ember v0.10.0 — Living World & Nine AI Kingdoms
- World radius 89: 24,031 hexes. Terrain is deterministic, generated on demand from axial coordinates and a saved world seed.
- Strategic map draws visible viewport cells only; it does not instantiate or persist 24,031 tile nodes.
- Nine AI kingdoms have independent capitals, rulers, cities, economies, armies and building/recruitment queues.
- Each turn every kingdom earns income, processes city development and recruitment, can expand and moves its army toward an objective.
- Added faction map markers and a kingdom overview panel.
- Strategic touch navigation supports drag, two-finger pan and pinch zoom; desktop supports middle-drag, wheel zoom and arrow keys.
- Battles can be started against any selected kingdom army and persist its survivors.
- Save JSON remains version 1 with additive world_seed and kingdoms fields; v0.9.x saves are migrated without discarding the player's city/army.
- Godot 4.3 GL Compatibility remains the target.
